# Limitações Conhecidas

- **Instância Única (Single-Instance):** Embora o componente de projeção de bordas (`ChromeLayer`) tenha sido isolado estruturalmente, a simulação visual de impressão continua fazendo manipulação de classe de escopo superior (`document.body.classList.add('print-mode')`). Como a impressão do browser possui natureza de exclusão global de viewport, o suporte perfeito para renderizar várias instâncias de editor simultâneas continua demandando revisão dessa dependência ou tratamento especial do Host.
- **Tabelas e Fragmentação:** Atualmente a fragmentação de tabelas é suportada nas fronteiras da linha (usando `table-row-spacer`). Regiões dentro de uma mesma linha (`TABLE_INTRAROW_UNSUPPORTED`), como células de texto muito grandes sem quebras internas ou expansões (`rowspan`/`colspan`) que ultrapassem os limites da página, não são fatiadas internamente.
- **Dom / Browser Dependence:** Toda a regra de paginação interativa acoplada em `PaginationController` depende nativamente do navegador via tamanhos calculados (`offsetHeight`, `getClientRects`). Portanto, este plugin não suporta renderização Server-Side.
- **Exportação Institucional e PDF Web:** Há uma diferença estrita entre a prévia visual e o backend institucional. O LayoutSnapshot estabilizado e o `print-mode` do browser oferecem fallbacks úteis, mas classificados apenas como `DEGRADED_COMPLETE` para contextos web. As exportações reais oficiais ainda emanam da arquitetura isolada Java/OpenPDF lendo a árvore de blocos (AST).
- **Semântica do LayoutSnapshot:** A ausência de diagnósticos no array nem sempre reflete um documento perfeito. Um estado `STALE_BREAK` evita o loop forçando um recuo de `lastBreakPos`, mas garante uma estabilização final. A promessa estabilizada é garantia de silêncio de layout, mas cabeletar diagnósticos deve ser feito cautelosamente.
